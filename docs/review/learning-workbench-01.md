# 学习工作台：中文 Review

## 本次结果

实现了已确认的三栏学习界面：左侧独立任务和审批，中间实际流程，右侧工具输入/输出与源码职责。没有扩展 RAG 查询或增加生产登录。示例语料位于 `examples/learning-corpus/`，含 4 年公开发布会摘要和 4 份虚构标准/政策。

## 重点检查

- 上传、文档选择、身份切换、runId 恢复、只读诊断和处理申请均通过现有 API；身份 header 不是认证。
- 模式以服务器返回为准。scripted 处理申请的 `Approve processing:` 前缀直接显示在问题框，不偷偷修改提交内容。
- 提议、审批、执行是不同节点。批准一次只对应一个已保存操作，后续 embedding 需要新的人工决定。
- 事件来自 PostgreSQL，有序号、runId 和 traceId；重连去重，不伪造成功，终态补齐历史后停止。
- 新增两个只读工具观察 API。所有权与文档权限重新检查，单次详情按白名单和大小限制投影，未知载荷明确省略。
- 切换身份取消旧请求并清空内容。sessionStorage 只保留身份范围内的最近 runId。
- 取消明确区分已请求和已完成，不承诺正在进行的写操作回滚。
- 源码职责是静态中文讲解，不声称是动态调用栈、隐藏推理或完整 tracing。

## 验证

- 后端完整测试：194 项通过，无跳过；专项观察测试覆盖 tenant/actor、PRIVATE 权限变化、跨 run 访问、分页、字段和大小限制。
- Worker：26 项通过，无真实模型调用。
- 前端：19 项单元/组件测试，4 项合成浏览器交互测试。
- 显式真实浏览器集成：1 项通过。临时 PgVector PostgreSQL、MinIO、Java、scripted worker、Chrome 真实跑完上传、CHUNK 审批、EMBED_MISSING 审批、最终报告、刷新恢复。数据库验证 1 份文档、3 个 parent、8 个 child、8 条 embedding、2 个成功 job。
- 桌面与手机截图检查、前端类型检查/构建；运行命令见 [操作指南](../learning-workbench.md)。

## 建议你手动看一次

先重启旧版本 Java 后端到本次代码，保持一个 scripted worker，打开 http://127.0.0.1:5173/。上传一份未处理的测试 Markdown，填入处理申请，逐次批准。点击每个节点的输入、输出和源码职责；最后刷新页面确认恢复。

## 保留的边界

没有真实登录/授权保障，没有多轮记忆、RAG 聊天、模型 token 流、公网部署或生产性能测试。白名单不等于 DLP；不要填入敏感资料。已有文档可能无须处理而没有审批。只测试 scripted 全链路，不声称真实 Pi 模型的审批行为已做同等验收。

未提交或推送 Git，未改动现有用户文档和正在运行的用户后端/worker。
