# Local Demo

This demo uses `examples/security-handbook.md`.

For harness Phase 2, use the [separate human-approval demo](agent-harness.md#human-approval-demo-phase-2).
For Phase 3 recovery/cancellation/SSE, use the [Chinese review and commands](review/agent-harness-phase-3.md).
`bash scripts/agent-events.sh "$RUN_ID" [LAST_EVENT_ID]` observes/replays events only; it never cancels or approves.
It deliberately stops at WAITING_APPROVAL and never approves automatically. A CHUNK
and a subsequent EMBED_MISSING require two separate decisions. The original RAG
demo below still invokes public ingestion endpoints directly.

## Prerequisites

The original demo below is unchanged. For the optional diagnostic harness, additionally install Node >=22.19, configure a private worker token, and run a separate worker. Follow [the Agent Harness demo](agent-harness.md#local-setup), then use `bash scripts/agent-demo.sh "$DOC_ID"`. Scripted execution needs no model key. One live run with OpenAI `gpt-5.6-luna` passed; see [its exact scope](verification/agent-harness-gpt-5.6-luna.md).

- Java 17 or newer.
- Maven 3.9 or newer.
- Docker running locally.
- `python3` for the helper script JSON parsing.

## Start Dependencies

```bash
make start-stack
```

Start the app in another terminal:

```bash
make run
```

Verify health:

```bash
scripts/demo.sh health
```

Expected shape:

```json
{"status":"UP","timestamp":"..."}
```

## Run The Demo

The demo works without tenant headers because missing headers use `tenant_id=default` and `actor_id=anonymous`. To exercise the enterprise-readiness skeleton manually, add:

```bash
-H "X-Tenant-Id: tenant-a" -H "X-Actor-Id: actor-1"
```

Upload the sample document:

```bash
scripts/demo.sh upload
```

The script saves the returned document ID to `.demo-document-id`.

Chunk the document:

```bash
scripts/demo.sh chunk
```

Embed child chunks:

```bash
scripts/demo.sh embed
```

Run hybrid retrieval debug:

```bash
scripts/demo.sh retrieval-debug
```

Build context:

```bash
scripts/demo.sh context-debug
```

Run the query API:

```bash
scripts/demo.sh query
```

Run SSE:

```bash
scripts/demo.sh query-sse
```

Run the agent workflow:

```bash
scripts/demo.sh agent-query
```

Inspect Redis keys:

```bash
scripts/demo.sh redis-keys
```

## One Command After The App Is Running

```bash
make demo
```

This runs health, upload, chunk, embed, retrieval debug, context debug, query, and agent query.

## Expected Output

The output should show:

- A document with status `STORED` after upload.
- Parent and child chunk counts after chunking.
- Embedded child chunk counts after embedding.
- Vector, full-text, and fused retrieval candidates.
- Citation-aware final context text.
- A local template answer with citations.
- Agent workflow status such as `COMPLETED`.

The answer is intentionally generated by `LocalTemplateAnswerGenerator`. It is a local placeholder, not production answer quality.

## Browser-Based Agent Processing Demo

The [learning workbench](learning-workbench.md) now has default **Knowledge QA** and separate **Document processing** views. QA uses the explicitly enabled real model pipeline with whole-library/selected-document scope, a real stage DAG and clickable parent/child citation evidence. Processing retains `/agent/runs`, separate CHUNK/EMBED_MISSING approvals and replayable task views. Run `make frontend` after installing frontend dependencies and restarting the updated Java backend. The Pi worker is only needed for processing. Default URL: http://127.0.0.1:5173/. See the [Phase 3 guide](learning/rag-03-learning-frontend.md) for configuration, explicit external-data/cost acknowledgement and two-scope curl examples. This paid path is separate from the offline demo above; no existing vectors are automatically migrated.

Upload individual TXT/Markdown files from [the learning corpus](../examples/learning-corpus/README.md), not its answer guide. It contains public Apple event summaries plus explicitly fictional business policies. Use a new unprocessed document to see both approvals. Already-processed documents can legitimately finish without an approval. This demo validates document processing and control flow, not semantic retrieval accuracy or business approval.
