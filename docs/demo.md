# Local Demo

This demo uses `examples/security-handbook.md`.

## Prerequisites

- Java 17 or newer.
- Maven 3.9 or newer.
- Docker running locally.
- `python3` for the helper script JSON parsing.

## Start Dependencies

```bash
make start-stack
```

Start the app in another terminal:

```bash
make run
```

Verify health:

```bash
scripts/demo.sh health
```

Expected shape:

```json
{"status":"UP","timestamp":"..."}
```

## Run The Demo

The demo works without tenant headers because missing headers use `tenant_id=default` and `actor_id=anonymous`. To exercise the enterprise-readiness skeleton manually, add:

```bash
-H "X-Tenant-Id: tenant-a" -H "X-Actor-Id: actor-1"
```

Upload the sample document:

```bash
scripts/demo.sh upload
```

The script saves the returned document ID to `.demo-document-id`.

Chunk the document:

```bash
scripts/demo.sh chunk
```

Embed child chunks:

```bash
scripts/demo.sh embed
```

Run hybrid retrieval debug:

```bash
scripts/demo.sh retrieval-debug
```

Build context:

```bash
scripts/demo.sh context-debug
```

Run the query API:

```bash
scripts/demo.sh query
```

Run SSE:

```bash
scripts/demo.sh query-sse
```

Run the agent workflow:

```bash
scripts/demo.sh agent-query
```

Inspect Redis keys:

```bash
scripts/demo.sh redis-keys
```

## One Command After The App Is Running

```bash
make demo
```

This runs health, upload, chunk, embed, retrieval debug, context debug, query, and agent query.

## Expected Output

The output should show:

- A document with status `STORED` after upload.
- Parent and child chunk counts after chunking.
- Embedded child chunk counts after embedding.
- Vector, full-text, and fused retrieval candidates.
- Citation-aware final context text.
- A local template answer with citations.
- Agent workflow status such as `COMPLETED`.

The answer is intentionally generated by `LocalTemplateAnswerGenerator`. It is a local placeholder, not production answer quality.
